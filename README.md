# dogo-tutor

愛媛・松山道後にある人間環境大学松山道後キャンパス総合環境学部環境情報学科の学びを
前面に出した、演習用チューターの VS Code 拡張です。答えではなくヒントだけを返し、
やり取りを記録して復習ノートと確認テストを生成します。

## 開発の手順

```bash
npm install
npm run compile
```

VS Code でこのフォルダを開き、F5 を押すと拡張開発ホストが起動します。
そちらのウィンドウで Copilot Chat を開き、`@tutor` と入力すれば動作を確認できます。

`npm run watch` を回しておくと、保存のたびに再コンパイルされます。
拡張ホスト側は Ctrl+R で再読み込みしてください。

## 学生に配る

```bash
npx vsce package          # dogo-tutor-0.0.1.vsix ができる
```

Marketplace に出す場合は Azure DevOps で発行者を作り、`package.json` の
`publisher` を書き換えてから `npx vsce publish` します。学生の操作は
拡張機能パネルで検索してインストールするだけになります。

学内配布に留めるなら .vsix を LMS に置き、学生には

```bash
code --install-extension dogo-tutor-0.0.1.vsix
```

を案内します。GUI なら拡張機能パネルの「…」から VSIX からのインストールです。

## 使い方

チャットで `@tutor` に質問します。開いているファイルが自動で添えられるので、
コードを貼り付ける必要はありません。400 行までなら全文が、それより長ければカーソル
前後 40 行が、行番号つきで渡ります。チューターは「12 行目の」のように行番号で指します。

添えられたファイルは応答の上に参照として表示されます。**意図しないファイルが出ている、
あるいは何も出ていないときは、チューターはそのコードを見ずに答えています。** 見せたい
ファイルをエディタで開いてから質問し直してください。

- `@tutor /next` 試したことを伝えて次の段階のヒントへ
- `@tutor /review` 直近 24 時間のログから復習ノートと小テストを生成
- `@tutor /log` 記録件数と、深いヒントに頼った割合を表示

## 設定

| 項目 | 既定 | 説明 |
| --- | --- | --- |
| `dogoTutor.subject` | 空 | 科目名。ノートのファイル名と見出しに使う |
| `dogoTutor.maxHintLevel` | 3 | 3 は擬似コードまで、4 は数行の部分コードまで許可 |
| `dogoTutor.reviewOutputDir` | `review` | ノートの出力先 |
| `dogoTutor.references` | 空 | 科目ごとの参考資料。下記参照 |

科目ごとに `.vscode/settings.json` で上書きすれば、演習ごとにヒントの上限を
変えられます。

## 参考資料の案内

チューターはヒントに参考資料のURLを添えます。ただし**案内できるのは実在確認済みの
一覧に載ったURLだけ**で、それ以外は URL を書かず検索語だけを示します。生成AIは
もっともらしい存在しないURLを作るので、リンク切れを踏んだ学生が調べること自体を
やめてしまうのを防ぐための制限です。組み込みの一覧には
Java API 日本語版、JDBCチュートリアル、Oracle JDBC開発者ガイド、dev.java、
Python 日本語版、MDN 日本語版が入っています。

講義資料を足すには `.vscode/settings.json` に書きます。

```json
{
  "dogoTutor.references": [
    {
      "label": "第5回講義資料 JDBC入門",
      "url": "https://lms.example.ac.jp/course/db2/week05.pdf",
      "topics": "接続文字列の書式と、演習用サーバの接続先"
    }
  ]
}
```

`topics` はチューターが案内先を選ぶ判断材料になるので、「どんなときに見る資料か」を
書いてください。`url` が `http://` `https://` で始まらない項目は無視されます。

## ヒントの段階

| 段階 | 内容 |
| --- | --- |
| `[ヒント1｜問いの整理]` | 何が分からないのかを言語化させる。解法には触れない |
| `[ヒント2｜方針]` | 方針を日本語で示す。使う概念やクラス名までは出す |
| `[ヒント3｜組み立て]` | 擬似コードや手順まで。そのまま動くコードにはしない |
| `[ヒント4｜部分コード]` | 1〜3 行の断片。既定では禁止 |

段階を上げるのは、学生が「何を試して何が起きたか」を述べたときだけです。
応答の冒頭にこの印が入り、これがログ解析に使われます。`maxHintLevel` の
1〜4 はこの段階の番号に対応します。

段階に関わらず、応答は学生がその場で5分以内に着手できる一手で終わります。**何を /
どこで / どうなったら完了か** が伝わることを求めていますが、見出しを立てて3行に
並べる書式は強制していません。毎回同じ型だと事務書類のようになって読まれないためです。

クラス名やメソッド名のような「調べれば載っている事実」は伏せません。暗記でしか
得られない知識を隠しても手が止まるだけで、考える力は育たないためです。伏せるのは
組み立て方であって、名前ではありません。綴り間違いや `import` の書き忘れも同様に、
遠回しにせず場所を伝えます。粘らせても学ぶものがないからです。

相手は初学者である前提で書きます。APIリファレンスは API の形をすでに知っている人の
資料なので、URL を貼って「読んでおいて」で済ませることはしません。必要なことは
日本語で説明し、URL は裏付けとして短く添えるだけです。

「エラーが出ました」とだけ言われたときは、直し方を推測で並べず、まずエラー本文を
出してもらいます。そのうえで **何行目か / 何という種類か / どの名前についてか** の
3点を学生自身に読み取らせます。エラーを読めるようになること自体が演習の目標だからです。

「できました」と言われたときは、次にやることだけを告げません。まず課題全体の地図と
現在地を示します（「接続 → SQL文の実行 → 結果の取り出し → 後始末 のうち1つ目が
終わりました」）。行き先が見えないまま次の作業を渡されても、学生は何をさせたいのか
分からず手が止まるためです。話題が変われば段階は 1 に戻ります。前の話題で 3 まで
進んだことは、新しい話題の段階とは関係がないからです。

渡す課題は一度に1つだけで、「その後」「できたら次は」と積み重ねません。ただしここでの
「1つ」は、**やり終えたときにコードが壊れていないまとまり**を指します。`Statement` を
`PreparedStatement` に替えるとき宣言の行だけ替えさせて実行の行を消させると、結果を
受ける変数が未定義になって学生は動けません。互いに依存する変更はひとまとめで渡します。
完了条件も、その変更で新たに出るエラーを含めて書きます。

また、問いかけとその答えを同じ応答に書きません（「なぜ必要かメモしてください
（〜だから）」は考える余地を自分で潰しています）。

応答の長さは学生の発話に釣り合わせます。「ENAMEです」のような一言に、状況確認・方針・
作業・完了条件をそろえるとくどくて読まれません。完了条件は、学生が自分では正誤を
判定しにくい作業のときだけ付けます。

発話が 12 文字以下のときは、1〜2 文で返させ、方針の宣言・完了条件・箇条書きを禁じる
指示を拡張側から注入します。プロンプトの文面だけでは守られなかったためです。

学生が知らないクラスや仕組みを持ち出すときは、名前を出すだけで終わらせません。
**それは何か / いまのコードの何が問題か / どういう順で使うものか** の3点を短く言います。

> `PreparedStatement` は、SQL の型紙を先に作って値を後から入れるためのクラスです。
> 19 行目は `?` を書いていますが、`Statement` には `?` に値を入れる手段がありません。
> 文を用意する → `?` に値を入れる → 実行する、の3段階で使います。
>
> ```java
> PreparedStatement ps = conn.prepareStatement(sql);
> ps.setString(1, value);
> ResultSet rs = ps.executeQuery();
> ```

3点目では呼び出しの形まで見せます。メソッド名や引数の形は調べれば載っている事実で、
考えて導けるものではないためです。添字が 1 から始まること、`Statement` と違って
`executeQuery` に引数を渡さないことのような、知らないと必ず止まる決まりもここで
言い切ります。

ただしこれは **「このクラスは一般にこう使う」という解説に留めます**。「18 行目を〜に、
19 行目を〜に変えてください」のように目の前のコードの書き換え手順まで書くことは
禁じています。`sql` や `value` に実際の SQL や変数名を当てはめた形も書きません。
**どの行にどう当てはめるかを考えるところが、課題として残す部分**だからです。

この3点は解答そのものではないので、`maxHintLevel` の上限とは別枠で、どの段階でも
伝えます。名前だけ出されても学習者は次に進めないためです。

ヒント1（問いの整理）は、質問が漠然としていて何に答えればよいか決まらないときだけ
使います。「入力した文字で ename 列を検索したい」のようにやりたいことが定まっている
質問をこの段階に留めると、意味のない作文課題になります。

### ちょい出し

まだ一行も書けていない学生には、読ませる前に**書かせます**。渡すのは解答の一部では
なく「入口の一手」です。

- 「`try { } catch (SQLException e) { }` の枠だけ書いてください」
- 「`DriverManager.getConnection(` まで打って、補完の候補を読んでください」
- 「接続に要る情報を3つの変数に分けて置いてみてください」

いずれも課題は解けませんが、その場で書き始められます。渡した一手について「候補が
3通り出るはずです」のように**結果を予告**するので、学生は自分で正誤を判定できます。

書いて渡してよいのは例外処理の枠や呼び出しの途中までといった「枠」だけで、引数の
中身や処理の順序は渡しません。枠には課題固有の論理が入っていないため、
`maxHintLevel` の上限とは別枠として扱います。

## ログ

`context.globalStorageUri/tutor-log.jsonl` に 1 行 1 レコードで貯まります。
1 レコードは時刻・セッション・科目・ヒント段階・ファイル名・質問・応答です。

成績評価に使うなら、生成した `review/*.md` をリポジトリに提出させるか、
`review.ts` の書き出し先を学内サーバへの POST に差し替えてください。
その場合は何をどこに送るかを学生に明示し、同意を取ってから運用してください。

## 既知の制約

学生は普通の Copilot Chat をそのまま使えるので、これは強制ではなく自習の枠組みです。
抜け道を塞ぐより、`/log` の「深いヒントに頼った割合」のような指標を可視化して、
自分の理解の浅さに気づかせる方向に倒すのが現実的です。
